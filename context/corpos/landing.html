Mods do Claude Code
— o curso técnico

A ideia que atravessa o curso

Um mod é três arquivos e uma função.

Um plugin.json, um hooks.json e um módulo que exporta register(on, options). Cada hook tem a forma ($, e, next) e entra numa cadeia com os outros plugins e o próprio Claude Code. Quem chama next deixa passar; quem não chama decide.

Com isso você conta o que o Claude toca, nega um comando perigoso, desenha uma faixa acima do prompt, abre um painel com botões e cria comandos que respondem sem gastar modelo — e prova tudo com claude plugin test.

Você, se programa (ou quase)

Sabe usar o terminal, já leu JavaScript ou TypeScript e já usou o Claude Code. Não precisa conhecer a API de mods: cada termo (hook, $, next, dispatch, superfície, matcher, atom...) é definido na primeira vez que aparece.

🏁 Projeto final: o seu mod

Um mod próprio, como o do Rafa: um comando /x, uma faixa ou um painel, estado em $.state, teste com claude plugin test (mocks antes do $), claude plugin validate OK, um botão ou comando para desligar e um README.

A prova: claude plugin test <pasta> com 0 fail e claude -p "/<comando>" --plugin-dir <pasta> respondendo sem modelo. Detalhes no módulo 4.4.

⚠️ Versão conferida

Tudo neste curso foi conferido no Claude Code 2.1.289, em 05/10/2026, numa máquina Linux ARM64. A API de mods está em acesso antecipado e muda entre versões.

A autoridade é o arquivo de tipos da sua instalação: .claude-plugin/types/claude-code/index.d.ts, que o Claude Code escreve dentro da pasta do mod quando ele carrega. O curso ensina a ler esse arquivo; nenhum nome é prometido para sempre.
